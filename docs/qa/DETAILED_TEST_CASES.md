# Nolia 详细测试用例库

> - 文档状态：目标版本全量测试基线
> - 适用分支：`codex/nolia-upgrade`
> - 适用平台：macOS 为当前主验收平台；Windows、Linux 在对应系统补做安装与系统集成
> - 最近更新：2026-07-12

## 1. 目的与范围

本文把 Nolia 的功能、数据完整性、外部文件、AI、插件、安全、性能、UI/UX、无障碍、迁移和安装发布要求转化为可执行测试用例。测试对象必须同时包含源码自动化、production build 和最终安装包，不能仅以开发模式通过作为发布依据。

范围包括：

- 工作区、主页、会话、健康检查和只读模式。
- 文件树、Markdown、资源文件、历史、草稿和冲突恢复。
- 外部单文件、多标签、临时文件夹和系统文件关联。
- Inbox、Daily Note、模板、属性、标签、链接、搜索和局部关系图。
- AI 聊天、内联修改、多文件审批、事务、回滚和权限边界。
- Plugin API v3 隔离、RPC、路径和网络安全；API v2 仅发现与迁移诊断。
- 性能、稳定性、无障碍、国际化、安装、升级和隐私诊断。

不在目标版本范围：云同步、多人实时协作、插件市场、移动端、Notion 式数据库、Canvas 和全局关系图。

## 2. 优先级、层级与结果

| 标记 | 定义 |
| --- | --- |
| P0 | 数据丢失、静默覆盖、权限逃逸、无法启动、迁移破坏等发布阻断问题 |
| P1 | 核心流程不可用、事务结果错误、主要平台严重回归，发布前必须修复 |
| P2 | 有替代路径但明显影响效率、可理解性或兼容性，可评估后发布 |
| P3 | 低影响视觉、文案或非主路径问题 |
| U | 单元测试，验证纯逻辑、schema、状态机或算法 |
| I | main/preload/数据库/文件系统集成测试 |
| E | Playwright renderer E2E |
| D | 最终安装版桌面人工或 Computer Use 验收 |
| S | 安全与对抗测试 |
| P | 性能、压力、稳定性或资源泄漏测试 |

结果统一记录为 `通过 / 失败 / 阻塞 / 不适用`。失败必须包含实际结果、预期结果、复现率、日志或截图位置、影响数据和关联缺陷。

## 3. 测试环境与数据集

| 环境 | 准备要求 |
| --- | --- |
| E0 干净环境 | 新 user-data、无最近记录、无 Provider、无插件、空临时目录 |
| E1 标准工作区 | 100 个 Markdown、10 个目录、图片/PDF/JSON/TXT/音视频/压缩包、标签/属性/链接/任务混合数据 |
| E2 真实工作区副本 | 用户真实文档的脱敏副本，禁止直接在唯一原件上做删除、AI 写入或迁移测试 |
| E3 大工作区 | 10,000 个 Markdown、1,000 个目录、深度 20、重复文件名、长路径、Unicode 路径、总数据至少 1GB |
| E4 外部文件集 | 四种扩展名、UTF-8 BOM、LF、CRLF、只读、非 UTF-8、空文件、100,000 字符、缺失和 symlink 文件 |
| E5 迁移集 | 当前 schema、旧 schema、损坏数据库、半写配置、旧 JSON AI task、超额历史快照 |
| E6 插件对抗集 | 合法 v3、v2、无效 manifest、越权文件、symlink、私网跳转、超时、崩溃和超大响应插件 |
| E7 AI 隔离集 | 独立 Provider 配置、测试工作区、限额密钥、可控 mock server、故意超时/空流/401/429/500 响应 |

通用边界数据：空字符串、全空白、1/255/256/1024 字符名称、保留字符、前后空格、`.`、`..`、绝对路径、混合分隔符、emoji、中日韩字符、组合字符、大小写仅不同的名称、最大层级、零字节和超大文件。

## 4. 执行约束

1. 所有破坏性测试只针对临时工作区或真实工作区副本。
2. 每个写入用例至少校验 UI 状态、磁盘正文、hash、历史或事务记录，不能只看成功提示。
3. 冲突测试必须保留双方内容，禁止把“最后写入者覆盖”视为通过。
4. AI Key 仅通过进程环境或应用安全存储注入，不写入本文、仓库、命令历史、截图或日志；报告中只记录 Provider、模型和脱敏 key id。
5. AI 自动化使用 mock 保证确定性；真实模型用于端到端连通性、工具调用和输出兼容性，不以内容措辞完全一致作为断言。
6. 安装版测试必须从最终 DMG/ZIP/安装器启动，使用全新路径冷启动，并检查应用日志。
7. 每轮全量测试结束后检查 unhandled rejection、renderer crash、open handle、watcher、文件描述符和残留子进程。

## 11. AI 功能、审批与事务

### 11.1 真实模型矩阵

| 目的 | 推荐模型 | 断言重点 |
| --- | --- | --- |
| 主聊天与工具调用 | `deepseek-ai/DeepSeek-V3.2` | 流式文本、tool call、来源、proposal 结构兼容 |
| 第二模型兼容 | `Qwen/Qwen3.5-35B-A3B` | 模型切换、中文指令、长上下文、结构化输出 |
| 低成本与弱模型边界 | `Qwen/Qwen3.5-9B` | 不完整 JSON、指令偏差时运行时仍守住权限 |
| 推理模型兼容 | `deepseek-ai/DeepSeek-R1` | 长思考/长首 token、取消、超时和 UI 不阻塞 |
| 向量索引 | `Qwen/Qwen3-Embedding-8B` | embedding 维度、批量、失败与重建 |
| 可选重排 | `Qwen/Qwen3-Reranker-8B` | rerank 不可用时降级，排序来源可解释 |

真实模型内容断言应基于“返回非空、语言合理、引用存在、工具/审批协议正确”，不要求逐字相同。视觉/多模态模型不属于当前正文 AI 主流程，不应为了覆盖模型列表扩大产品范围。

## 19. 发布准入与阻断

必须全部满足：

- P0 通过率 100%，不得豁免。
- P1 通过率 100%；被外部平台阻塞时必须有证据、风险说明和明确补测责任人。
- typecheck、lint、unit、E2E、production build、`git diff --check` 全部通过。
- 六项性能预算全部有本轮数据，不能沿用历史结果。
- 最终安装版冷启动、文件关联、保存冲突、关闭握手和升级迁移通过。
- 日志无 unhandled rejection、renderer/main crash、preload failure、open handle 和资源泄漏。
- API key、正文、授权 header 等敏感信息未进入仓库、报告和普通日志。

直接阻断发布的典型问题：正文丢失或静默覆盖、迁移不可回退、AI/插件越权、事务部分失败显示成功、安装版无法打开、dirty 关闭绕过守卫、错误包架构或文件关联不工作。
